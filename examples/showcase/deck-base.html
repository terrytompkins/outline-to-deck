Why outline first

  • Text is cheap to write, revise and re-read; a finished deck is expensive on all three.
  • Every "redo the deck" pays for the whole deck again.
  • Coding agents are advised to work the same way: plan in text, approve, then build.

Structure maps to slides

Freeze numbering from v0.2 on. New sections get the next number; the time plan sets the order.

The approval gate

  • DECISIONS.md logs dated decisions as Proposed or Decided.
  • The gate line: Decided · Outline v1.0 approved; Phase 2 begins.

Without the gate line, a casual "can I see a slide?" starts Phase 2 early and the deck drifts from the outline.

Where does a speaker note end up?

An outline line starts with Speaker notes:. Where does it appear in the deck?

  1. On the slide, in small text
  2. In the presenter view only
  3. In the agenda
In the presenter view only. It is never visible on the slide.
Pause for answers before revealing.

Tag one section

Time: 5 minutes

  1. Pick a section of a talk you are working on.
  2. Rewrite it as ## N. Title with three main points.
  3. Add one callout where it fits: a tip, a hazard or something to remember.
a section that already reads like a horizontal slide, with one tag the deck will render.

Phase 1 in three points

  • Numbered sections become slides.
  • State files, not chat history, carry progress.
  • Approval is a recorded decision.

Tags

  • A tag says what a piece of content is; the style decides how it looks.
  • Callouts use GitHub's alert syntax, so outlines stay readable.
  • One registry, TAGS.md, defines every tag.
